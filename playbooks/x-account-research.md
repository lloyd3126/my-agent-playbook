# X 帳號研究與持續更新

## 目的與界線

整理指定 X 帳號在特定期間內公開發布的原創貼文、引用貼文與回覆，建立可追溯且能持續更新的研究紀錄。這不是人格模仿、投資建議、私訊策略，也不授權 Agent 與該帳號互動。

預設只讀：不按讚、不追蹤、不收藏、不轉發、不回覆、不發布貼文。

## 輸入與輸出

開始前確認：

- 帳號名稱與直接 URL
- 模式：首次整理、近 7 天更新、事件追查或歷史整理
- 日期範圍；歷史整理未指定範圍時要先詢問
- 是否包含純轉發；預設排除
- 研究用途與需要獨立驗證的議題

每個帳號輸出到 `knowledge/x/accounts/<handle>.md`。文件前方是目前彙整，後方是追加式來源紀錄。

## 環境確認與啟用

這個 playbook不需要 Python 或 X API 套件。優先使用 Agent 可控制、且由使用者自行登入的瀏覽器工作階段。

1. 確認 Agent 是否能操作內建瀏覽器或 Chrome 分頁。
2. 確認 X 網站可達、帳號頁可讀，以及登入是否影響結果完整性。
3. 若需要登入，使用者直接在 X 登入畫面操作；Agent 不索取密碼、cookie 或驗證碼。
4. 若沒有瀏覽器控制能力，改用公開網頁搜尋並在結果中標明可能遺漏；不要聲稱已完整抓取帳號時間軸。
5. 若使用者希望長期保存，確認 repository 可寫與目標 knowledge 路徑；如果只要一次摘要，先詢問是否需要寫入。

主機端瀏覽器 connector／擴充能力如尚未啟用，由使用者依其主機應用程式介面啟用。不要為了研究 X 安裝未經確認的抓取器、提供 cookie 給第三方，或規避 X 的存取限制。

## 研究模式

### 首次整理

- 預設回溯近 1 個月可見內容。
- 建立主要研究主線、反覆出現的公司、分析方法、時間框架與作者明確揭露的立場。
- 保存每則原文短摘錄和直接連結。

### 日常更新

- 預設最近 7 天。
- 先讀既有帳號文件，避免重抓與重複來源。
- 比較新內容是否延續、改變或推翻既有觀點。

### 事件追查

- 事件前預設回溯 1 個月，並整理事件後至今。
- 把事件時間、作者事前看法、事件後反應與獨立驗證分開。

### 歷史整理

- 使用者指定起訖日期；未指定時先詢問。
- 按月或按事件分批處理，保存每個區間的完成、失敗與待續狀態。
- 只有所有指定區間都成功取得、去重並核對後，才稱為完整重建。

## 蒐集與分類流程

1. 記錄目前日期、帳號、查詢範圍、登入狀態與蒐集方式。
2. 若已有 knowledge 文件，先讀前方彙整與後方來源紀錄。
3. 使用帳號時間軸與依帳號篩選的搜尋，逐批取得指定期間內容。
4. 每則記錄日期、作者、類型、原文短摘錄、直接連結、回覆對象與引用來源。
5. 類型判定優先使用結構化 metadata、作者／日期區塊、引用卡片與關聯連結：
   - 明確標示回覆且有對象才分類為回覆。
   - 有引用卡片或引用來源才分類為引用貼文。
   - 兩者皆無才分類為原創。
   - 證據不足或互相衝突時標記「待確認」。
6. 回覆至少保留作者自己的貼文連結、回覆對象，以及能取得時的上層原文與連結。
7. 檢查 `原創 + 引用 + 回覆 + 待確認 = 總筆數`，抽查分類邊界後才寫入文件。
8. 先更新文件前方彙整，再把新來源追加到後方；不刪除舊來源，錯誤以修正註記處理。

## 限流與可恢復進度

以下是保守操作預設，不是 X 保證的固定限制：

- 使用單一分頁與單線流程，不同時搜尋多個帳號。
- 初次開頁等待約 5 秒；每次捲動後等待約 3–5 秒並確認新內容。
- 切換查詢區間至少間隔 20–30 秒；相同查詢重新載入至少間隔 60 秒。
- 約 10–15 次捲動後保存來源與進度，避免一次追完整年。
- 日期先以一個月切分；內容過多或載入不穩時再縮成半月或 7 天。
- 已完成區間不重抓；分開記錄「網站錯誤」「限流」「沒有結果」。
- 發生錯誤時冷卻 2–5 分鐘，原查詢最多重試一次；連續兩個區間失敗就暫停。

## 輸出格式

1. 帳號、期間、搜尋方式、取得數量與限制。
2. 一段近期主線摘要。
3. 按主題整理作者觀點、涉及標的與已揭露立場。
4. 逐則來源：日期、類型、原文短摘錄、中文摘要、相關實體、直接連結。
5. 觀點變化、未獨立驗證資訊、待補內容與可能遺漏。

作者原話、引用他人內容、Agent 摘要與 Agent 推論必須清楚區分。金融、政治、政策與市場傳聞不得只依貼文判定為事實。

## 持續使用與教學

下次可直接說：

> 依照 X 帳號研究 playbook，更新 `knowledge/x/accounts/serenity.md` 最近 7 天內容，沿用既有分類並列出觀點變化。

> 研究這個 X 帳號從 2026-01-01 到 2026-03-31 的公開內容，先建立分批計畫與可恢復進度，不要互動。

每次完成後要回報完成區間、未完成區間、最後成功日期與下次應從哪裡繼續。

## 停用與完整移除

本流程沒有必需的本機套件。要停止或移除時：

1. 停止任何排程或監看任務。
2. 關閉研究分頁；需要時由使用者自行登出 X。
3. 在主機應用程式中停用瀏覽器控制連線；若使用者另裝擴充功能，依其官方程序移除。
4. knowledge 文件是使用者資料，預設保留。只有使用者指定精確路徑並確認後才刪除。
5. 若曾手動匯出 cookie、token 或瀏覽器資料，先撤銷／登出對應工作階段，再刪除匯出檔；不得把它們 commit 到 repository。
