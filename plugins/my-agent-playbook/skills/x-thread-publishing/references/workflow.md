# X 串文發布

## 目的與界線

把長內容拆成容易閱讀、前後相連的 X 串文。這個流程會改變外部帳號狀態；Agent 可以協助草擬與操作，但沒有使用者對最終內容和目標帳號的明確確認，不得發布。

不包含自動排程、批量私訊、按讚、追蹤、轉發或刪除既有貼文。

## 所需環境

這個 playbook 不需要安裝 Python、Node.js 或 X API 套件。需要：

- 一個 Agent 能操作的瀏覽器分頁，或由使用者手動操作的瀏覽器
- 可正常開啟 X 的網路
- 使用者已在瀏覽器內登入正確帳號
- 使用者提供的原始內容、回覆目標和發布順序

### 從完全沒有工具開始

1. Agent 先確認目前是否有可控制的內建瀏覽器或 Chrome 工作階段。
2. 若沒有，使用者在主機應用程式中啟用其支援的瀏覽器控制能力，或改採手動發布模式。
3. 使用者自行開啟 <https://x.com/> 並登入；密碼和驗證碼只輸入 X 的登入畫面，不貼給 Agent。
4. Agent 以唯讀方式確認目前帳號名稱、目標貼文和編輯器是否可用。
5. 若瀏覽器控制仍不可用，Agent 只交付逐則草稿、字數與回覆順序，由使用者手動貼上。

瀏覽器能力的安裝／啟用方式會隨使用的 Agent 主機而不同，因此不要執行來路不明的擴充功能或要求使用者交出瀏覽器 profile。

## 首次發布流程

1. 確認正確帳號、目標貼文 URL、內容語言與希望的段數。
2. 將內容拆成：
   - 不編號的開場文字
   - `[1 / N]` 到 `[N / N]` 的正文
3. 保留語意完整的段落，不用分隔線填充，也不要把多個編號塞入同一則。
4. 檢查每則長度、連結、標點、提及帳號與編號是否正確。
5. 把完整預覽交給使用者確認；任何發布動作都在確認之後。
6. 發布開場文字，再依序回覆自己的上一則貼文形成 thread。
7. 若使用者要求逐則檢查，每發布一則就暫停；若使用者已確認全部內容並要求完成，才連續發布剩餘內容。
8. 最後逐則開啟確認順序、內容與直接連結，回報成功或失敗。

## 發布前檢查

- [ ] 瀏覽器顯示的是使用者指定帳號
- [ ] 目標貼文與回覆對象正確
- [ ] 使用者看過最終文字
- [ ] 編號總數一致，沒有缺號或重號
- [ ] 每則沒有意外的草稿、附件或錯誤提及
- [ ] 已知道失敗時要停止在哪一則，不會整串重複發布

## 持續使用與教學

下次可以直接對 Agent 說：

> 依照 X 串文發布 playbook，把下面內容拆成 4 則。先只給我預覽，不要發布。

> 我已確認剛剛的 4 則內容，請用目前登入的帳號回覆這個 URL，完成後給我每一則連結。

如果 X 改版，Agent 應重新確認編輯器、回覆關係與已發布結果，不依賴舊的 CSS selector。

## 失敗處理

- 發布按鈕不可用：先檢查字數、登入狀態、帳號限制與網路，不重複點擊。
- 不確定是否已送出：重新載入個人頁面或 thread 確認，未確認前不要重發。
- 發到錯誤帳號或內容錯誤：立即停止後續發布，列出已發布連結，讓使用者決定是否刪除；Agent 不自行刪除。
- 被限流或出現錯誤：保存未發布草稿與下一個編號，等待後再從正確位置繼續。

## 停用與完整移除

本流程沒有安裝本機套件，通常不需要 uninstall。若使用者要完全停止：

1. 確認沒有未送出的 X 草稿或背景自動化。
2. 關閉 X 分頁；需要時由使用者自行登出 X。
3. 在 Agent 主機設定中停用瀏覽器控制能力；若曾另外安裝擴充功能，依該擴充功能官方方式移除。
4. 只有使用者明確要求時才刪除本機草稿或發布紀錄。
5. 不刪除已發布貼文；那是另一個需要逐一確認的外部變更。
